v4, step by step

We follow the example S1 above. Training trick used everywhere: the training S1s are split into 5 groups, and each group is scored only by models that never saw it ("out-of-fold"), so every score is as honest as on test.

A second-opinion matcher

src/v2/

A simpler matcher, built independently, gives every pair its own probability. We don't submit it: its score becomes one input of the final model, like asking a second expert.

Technical
e5-small search (25 per S1, 5 S1 per record) + IDF shared keys → 44 pair features → LightGBM, 5-fold GroupKFold by S1 → isotonic calibration → out-of-fold p_v2. Own macro F0.5 0.9781; 17.5% of stage 3's gain.

Clean the text

prepare.py · text.py · lexicon.py

Copies are written differently, so everything is put into one standard form first. The replacement rules are learned from the training answers, not typed by hand.

Example: Sóns → sons, AP → andhra pradesh, Pvt → private; core name shree sons (generic words removed); house number 63.

Technical
keep u → v if n(u→v) ≥ 20 and n(u→v) / n(u) ≥ 0.5 (u in the copy only, v in the S1 only, over true pairs) generic(w, country) ⇔ share of that country's names containing w ≥ 1%
≈ 2,000 name and 700 address mappings; generic words from each split's own records (US 40, India 64, France 77). Also mojibake repair, alias split, OCR repair, consonant skeleton, metaphone, typed numbers, uniqueness counts.
polarsanyasciijellyfish

Turn text into numbers

embed.py

Two language models turn each record into a list of numbers (a vector). Records that mean the same thing get vectors pointing the same way, even across spelling or script.

Example: the Hindi-script copy and the English S1 end up with close vectors.

Technical
e(x) = f(x) / ‖f(x)‖ cos(a, b) = e(a) · e(b)
Input "name | address", fp16, max 64 tokens. e5-large is stronger overall and on native script, e5-small on records without an address, so both are used.
multilingual-e5-small (118M, MIT)multilingual-e5-large (560M, MIT)sentence-transformerstorch
3

Search for candidates, within each country

block.py · sketch.py

Comparing an S1 with millions of records is impossible, so several fast searches each propose likely candidates. The goal here is to miss nothing: look-alikes are rejected later.

Example: both copies and the look-alike "Shree Holdings" are found.

Technical
forward: top-25 records by cos(a, ·) reverse: each record's top-5 S1 sketch: s_j(x) = Σ_{g: h(g)=j} σ(g)·tfidf_g(x), j = 1..256 (E[s(a)·s(b)] = tfidf cosine) keys: sp(a, b) = Σ_{shared rare keys k} log(N / df(k)) → top 20; 6 exact keys, capped at 10 S1 / 50 records
Recall alone: e5 forward 0.961 / 0.963, reverse 0.975 / 0.980, address sketch 0.809, name sketch 0.626. Union: 0.9908 at 92 pairs per S1. Exact GPU search at this size; FAISS IVF for larger data.
torch (GPU nearest neighbours)scikit-learnscipyfaissrecall 0.9908

A search model trained on our data

retriever.py

We took e5-small and trained it on the training answers: "these two texts are the same business". It learns what "same" means in this data and finds copies the other searches missed.

Technical
L = −(1/B) Σ_i log [ exp(20·cos(q_i, d_i)) / Σ_j exp(20·cos(q_i, d_j)) ] B = 256, lr 2e-5
InfoNCE with in-batch negatives; romanized copies of native script as extra positives; cross-fitted in 2 halves of S1 on train. Adds top 10 per S1 and top 3 S1 per record. Removes 61% of the true pairs the other routes missed.
fine-tuned e5-small ×3sentence-transformerstorchrecall 0.9964 at 110 per S1
5

Shortlist the best candidates

stage1.py

A fast model scores all ~110 candidates with cheap clues and keeps only the best few per S1, so the careful model later has less to check.

Example: the two copies and the look-alike are kept; about 100 unrelated records are dropped.

Technical
p1 = σ( Σ_m η·f_m(x) ) gradient-boosted trees, log-loss (K, τ) = argmin |S| / N s.t. recall(S) ≥ 0.999 · recall(pool) → K = 10, τ = 0.003
XGBoost (GPU), 51 cheap features, η = 0.1, ≤ 1,500 trees, depth 9, subsample 0.8, 5-fold out-of-fold. Top features: e5-large reverse rank 52%, e5-large cosine rank 19.5%, same house number 8.8%, retriever rank 4.3%.
XGBoost, 5 × ~1,500 treesxgboostrapidfuzzrecall 0.9955 at 5.85 per S1

Measure every candidate in 101 ways

features.py

For each shortlisted pair: how similar are the names, the addresses, the house numbers? How rare are the shared words? Is this the S1's best candidate, and by how much?

Example: copy — name ≈ 100%, house number 63 = 63, rank 1. Look-alike — only "shree" shared, 12 ≠ 63, far behind.

Technical
ratio = 1 − d_indel(x, y) / (|x| + |y|) J_idf = Σ_{A∩B} idf(w) / Σ_{A∪B} idf(w) gap_a(b) = p1(a, b) − max_{b'≠b} p1(a, b') mutual best = [b best for a] ∧ [a best for b]
Name: ratio, token-sort/set, partial, Jaro-Winkler on full/core/compact/OCR names, aliases, initials, metaphone, skeleton, typos. Address: similarities on full/core address, abbreviation coverage, typed-number relation. Plus retrieval ranks, uniqueness counts, listwise ranks and gaps. Country is not a feature.
rapidfuzzjellyfishpolars

The main matcher

train.py · learner.py · decide.py

A model learns from 7.6 million labelled training pairs how to combine the 101 measurements into one probability, then that probability is adjusted so that "0.9" really means right 9 times out of 10.

Example: copy → p2 ≈ 0.99; look-alike → p2 ≈ 0.02.

Technical
fold(a) = hash(a, 13) mod 5 p̂_i = σ(F^(−fold(a_i))(x_i)) (out-of-fold) g = argmin_{g non-decreasing} Σ (y_i − g(p̂_i))², p2 = g(p̂) (isotonic calibration)
XGBoost, η = 0.05, ≤ 5,000 trees with early stopping (~3,000–3,500 used per fold; final 3,496), depth 9. A per-S1 "has any match" model runs alongside.
XGBoosthas-any-match XGBoostxgboostscikit-learnscore 0.9888

A careful reader for unsure cases

crossenc.py

For pairs where the matcher is unsure, a language model reads both records together, word by word, and gives its own opinion. It catches things the measurements miss, like one word turning a business into a different one.

Technical
p_ce = σ( wᵀ · Enc("name: … | address: …"_a ‖ "name: … | address: …"_b) + b₀ ) only if 0.02 ≤ p2 ≤ 0.98
Base multilingual-e5-small + 1-logit head, max 96 tokens, lr 3e-5, batch 256, 1 epoch, binary cross-entropy on the band + 5% of confident pairs; 2-fold cross-fitted by S1; test = mean of both.
cross-encoder ×2transformerstorch

Does it fit the group?

graph.py

A real copy looks like the other copies the S1 already has. A record that another S1 wants even more is suspicious.

Example: the Hindi copy resembles the English copy already held, which supports it.

Technical
g1 = max_{a'≠a} p2(a', b) g2 = max_{b'≠b} p2(a, b') g3 = max_{b' ∈ Sib(a)} cos(b, b') Sib(a) = { b' : p2(a, b') ≥ 0.5 } (also mean, other-source-only, name similarity)
polarsnumpy

The final model combines every opinion

stage3.py

One more model takes the measurements plus every earlier opinion (main matcher, careful reader, group check, second-opinion matcher) and gives the final probability.

Technical
x = [ 96 pair features (5 candidate counts dropped), p2, p_ce, g1..g6, p_v2 ] (105 inputs) → XGBoost → isotonic → p
105 inputs, same folds (leak-free stacking), ~800 trees per fold, final 886. Gain share: p2 69%, p_v2 17.5%, p1 8.4%, p_ce 2.7%, graph ≈ 0.7%.
XGBoost + has-any-matchxgboostscikit-learnscore 0.9913

The final decision

Each record can belong to only one S1: the one that wants it most. Then only confident pairs are kept. We set the bar high (0.95) because the test data has twice as many look-alikes as the training data.

Example: both copies kept (p ≈ 0.999); "Shree Holdings" rejected.

Technical
a*(b) = argmax_a p(a, b) M(a) = { b : a*(b) = a, p(a, b) ≥ 0.95 } F0.5(a) = 1.25·TP / (1.25·TP + 0.25·FN + FP), score = mean over all S1
Best threshold on train: 0.70 (leaderboard 0.983). At 0.95: 0.984312. At 0.99: 0.980. Comparing leaderboard scores of cuts showed the 0.95–0.99 band is ≈ 85% right on test against ≈ 95% on train.

v5: what is extra

Same code as v4 with three switches turned on. It reuses v4's candidates, so both models judge exactly the same shortlist.

Same as v4

  • text cleaning and learned rules
  • vectors and every search (candidates copied from v4)
  • 101 measurements, main matcher, careful reader, group check, final model
  • decision rule

Changed in v5

  • 1. practise on test-like data: 19% of training S1s hidden
  • 2. learn each country's abbreviations from the records
  • 3. shortlist model allowed 3,000 trees instead of 1,500

1 · Practise on test-like data

An "orphan" is a record whose S1 is not in the data: a look-alike with no true owner. Test has about twice as many as train. v5 hides 19% of the training S1s, so their copies become orphans. The model then practises saying "no" as often as test requires.

Technical
S1 dropped by hash(id, seed+99) after the pool is built: 2,206,821 → 1,786,233 S1; pool 243.8M → 197.3M pairs; reverse-route ranks re-ranked among the remaining S1; ground truth read through the kept S1 only. Stage 1 → stage 3 are then learned under this density (s1drop.py).

2 · Learn abbreviations from the records

No answers needed. Records that share a house number and a rare word are almost certainly the same place; where one writes a short word and the other a long one, the short one is probably an abbreviation. This gives France a vocabulary even though France has no training answers.

r → ruebd → boulevardets → etablissementsst → saint
Technical
Candidate short→long if same first letter and the short word's letters appear in order in the long one; kept if ≥ 30 occurrences and ≥ 50% consistency; per country; applied before the lexicon (mining.py).

3 · A bigger shortlist model

v4's shortlist model hit its limit of 1,500 trees in every group (1,446–1,499), so it was still improving. v5 allows 3,000.

v5 alone: train 0.9910 (harder data) · leaderboard 0.98376

The submission: blending v4 and v5

The two models make different mistakes, so we average them, trusting v4 more. We keep exactly as many pairs as v4 alone did at 0.95, so the blend only swaps v4's weakest pairs for better ones.

Technical
p = 0.7·p_v4 + 0.3·p_v5 a*(b) = argmax_a p(a, b) t = n*-th largest winning p, n* = |v4 pairs at p ≥ 0.95|
t = 0.9157, 5,836,213 pairs. Weights chosen on the 1,782,911 training S1s v5 kept, at equal pair count: 0.7/0.3 best of 14 weightings and 3 voting rules (0.99031 vs v4 0.99021). src/run_final.py reproduces the uploaded file byte for byte.

Words used on this page

Recallshare of real copies that are still kept.
Precisionshare of kept pairs that are real copies.
F0.5a score that weighs precision more than recall; a wrong match costs about 3× a missed one.
Out-of-foldeach training S1 is scored by a model that never saw it, so scores behave like on test.
Calibrationadjusting scores so that "0.9" means right about 90% of the time.
